# 🛠️ Dynamic SQL Query Automation

Dynamic SQL Query Automation is a **Flask-based CRUD web application** that demonstrates how **dynamic SQL queries** can be used to perform real-time database operations on a MySQL backend.
The project emphasizes **clean backend abstraction, correct database design, and practical error handling**, making it suitable for both learning and portfolio use.

---

## 🚀 Key Features

* 🔄 **Complete CRUD Operations**
  Create, read, update, and delete user records through a web interface.

* 🧱 **Modular Backend Architecture**
  All database logic is encapsulated inside a dedicated `DBHelper` class, ensuring clear separation of concerns.

* 🆔 **AUTO_INCREMENT Primary Key Design**
  User IDs are automatically generated by MySQL to guarantee uniqueness and data integrity (industry-standard practice).

* ⚠️ **Robust Error Handling**
  Database constraint errors are handled gracefully and communicated to the user via UI feedback.

* 📝 **Logging System**
  Backend operations and errors are logged to a file for debugging and traceability.

* 🌐 **Modern Web Interface**
  Clean and responsive UI built using HTML, CSS, and Tailwind CSS.

## 🔧 Setup & Run Locally

### 1️⃣ Install Required Packages

```bash
pip install flask mysql-connector-python
```

---

### 2️⃣ Configure MySQL Database

Create a database:

```sql
CREATE DATABASE dynamic_sql;
```

Update database credentials inside `db_helper.py`:

```python
self.con = connector.connect(
    host="localhost",
    user="your_username",
    password="your_password",
    database="dynamic_sql"
)
```

The application automatically creates the required table if it does not already exist.

---

### 3️⃣ Run the Flask Application

```bash
python app.py
```

---

### 4️⃣ Open in Browser

```
http://127.0.0.1:5000/
```

## 🧠 Design Decisions

* **AUTO_INCREMENT IDs**
  User IDs are immutable identifiers generated by the database.
  Gaps in IDs after deletions are intentional and reflect real-world relational database behavior.

* **Dynamic SQL Without ORM**
  Raw SQL queries are used instead of an ORM to clearly demonstrate query construction, execution, and constraint handling.

* **Separation of Concerns**

  * Flask routes manage request/response logic
  * `DBHelper` manages database interaction
  * Templates handle presentation only
